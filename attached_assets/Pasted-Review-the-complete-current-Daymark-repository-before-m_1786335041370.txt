PART 6: AUTHORIZATION HARDENING
==================================================

Authentication has been implemented, but audit authorization deeply.

STRICT OWNERSHIP

Every user-owned record must require an exact ownership match.

Do not allow records with userId null to be opened by authenticated users.

Handle legacy null-owner records safely:

- assign them to a dedicated demo account
- migrate them to an intended owner
- or hide them from regular user queries

Do not expose legacy rows through guessed IDs.

PERSON ID VALIDATION

When creating or updating a memory:

- verify every personId belongs to req.user.id
- reject foreign or invalid IDs
- use a database transaction
- do not partially create links

Apply the same rule to Future Gift recipient links.

RELATED DATA

Do not fetch people or media belonging to another user through relationship tables.

Verify ownership before assembling the response.

RESOURCE ACCESS

For unauthorized resource IDs, prefer 404 where revealing existence would be unsafe.

STORAGE

Confirm:

- uploaded objects belong to the authenticated user
- private photos cannot be accessed by another user
- object paths cannot be guessed to retrieve another user’s media
- explicitly shared memories are the only exception

SSE

Personal events must be sent only to their owner.

Shared-memory events may go only to accepted participants.

Never send private memory contents inside SSE payloads.

Send only identifiers.
