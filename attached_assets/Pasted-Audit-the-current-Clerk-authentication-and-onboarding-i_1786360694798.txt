Audit the current Clerk authentication and onboarding implementation before editing.

CURRENT PROBLEM

Daymark currently uses Clerk's generic SignIn and SignUp screens.

The current experience feels ambiguous because a user enters an email first
without clearly choosing whether they are:

1. an existing Daymark user
2. creating a new Daymark account

Redesign authentication into TWO explicit flows.

Do NOT replace Clerk.

Do NOT add Supabase Auth.

Keep:

AUTH = Clerk
DATABASE = Supabase/Postgres when migrated
APP USER PROFILE = Daymark users table
