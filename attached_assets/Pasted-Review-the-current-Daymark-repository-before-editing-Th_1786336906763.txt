IMPORTANT:

The recipient must be an authenticated Daymark user and an accepted connection.

Do not auto-send messages to arbitrary phone numbers, WhatsApp accounts, Instagram accounts, or emails without an explicit supported integration.

Delivery occurs INSIDE DAYMARK.

At the scheduled time:

1. server checks due scheduled messages
2. confirms recipient still exists
3. confirms connection is still permitted
4. marks message sent atomically
5. creates recipient notification
6. emits real-time SSE event
7. makes message visible in recipient inbox
8. records sentAt

Never rely only on an open browser tab.

Scheduling must happen server-side.

PART 14: SERVER-SIDE SCHEDULER
==================================================

Scheduled messages must work even if nobody has Daymark open.

Implement a durable server-side scheduling mechanism compatible with the current deployment environment.

Do not use browser setTimeout.

Preferred architecture:

- database stores scheduled messages
- background/cron worker periodically checks due messages
- row-level locking or atomic update prevents duplicate sends
- sent status persisted
- notification created
- SSE used only for immediate UI delivery if recipient is online

The database is the source of truth.

Scheduler should be idempotent.

A message must never be delivered twice.
