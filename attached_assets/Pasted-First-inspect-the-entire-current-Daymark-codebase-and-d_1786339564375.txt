==================================================
PRODUCT PRINCIPLE
==================================================

Daymark is NOT Instagram, Snapchat or a generic social network.

Its product loop is:

KEEP
Save your own little moments.

CONNECT
Build a private shared history with people you care about.

DISCOVER
See small, opt-in everyday moments from around the world.

RETURN
Rediscover the past, continue Daylinks and receive things saved for the future.

The user's own memories remain the center of Daymark.

==================================================
7. WHAT COUNTS FOR DAYLINK
==================================================

A relationship can earn at most ONE Daylink day per calendar day.

Qualifying actions:

- create a shared memory together
- send a Memory Drop and recipient opens/reacts
- answer Today's Little Question together
- add a new moment to an existing shared memory
- exchange another explicitly meaningful Daymark interaction

Do NOT count:

- opening the app
- profile views
- repeatedly reacting
- searching someone
- generic notification opens
- Globe interactions

Public Globe activity NEVER counts toward Daylink.

26. SERVER-SIDE DELIVERY
==================================================

Scheduled messages MUST work while the sender is offline.

Do NOT use:

setTimeout in browser

Use:

database-backed scheduled jobs / cron-compatible worker.

The database is the source of truth.

Delivery must be idempotent.

Never send the same scheduled message twice.

When due:

1. atomically claim scheduled message
2. verify recipient still exists
3. verify sender is allowed to deliver
4. mark sent
5. create recipient notification
6. emit minimal SSE event if recipient is online
7. make message available in recipient inbox
